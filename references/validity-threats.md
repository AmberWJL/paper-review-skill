# Validity threats for empirical ML/CS papers

Use this when writing the Adversary section. For each threat, the test is the same: *if the
claimed contribution were removed, could something else explain the result?* and *how narrow is
the setting in which the claim has actually been demonstrated?*

## Construct validity — does the evaluation measure the claim?

| Threat | What to look for | Typical tell in the paper |
|---|---|---|
| Proxy metric | Metric is a stand-in for the real objective (BLEU for quality, pass@1 for "reasoning", perplexity for usefulness) | Claim is about X, every table measures Y |
| Benchmark artifacts | Dataset solvable by shortcuts, label noise, saturated benchmark, answer-only matching | Gains concentrate on one benchmark; no human eval |
| Contamination | Test data in pretraining or fine-tuning corpus; synthetic data generated by a model that saw the test set | No contamination check; data generated by a frontier model; benchmark predates the training corpus |
| Inappropriate setup | Zero-shot vs few-shot mismatch, different prompts per method, evaluation at a different scale than training | Setup described only in the appendix or not at all |
| LLM-as-judge | Judge is the same family as the policy, judge prefers length/style, no human agreement reported | Win rates without human calibration |
| Metric-objective mismatch | Optimizing the metric directly (reward hacking, test-set tuning) | Reported metric is also the training signal |

## Internal validity — is the improvement attributable to the method?

| Threat | What to look for | Decisive check |
|---|---|---|
| Unfair baselines | Baselines not re-tuned, older checkpoints, weaker prompts, fewer steps | Did the authors tune baselines as hard as their method? |
| Compute / data / size confounds | More tokens, more steps, bigger model, extra data (e.g. synthetic) only for the proposed method | Matched-compute or matched-data comparison |
| Hyperparameter asymmetry | Search budget reported for method but not baselines | Same sweep for all |
| Missing ablations | No experiment removing the claimed key component | Ablation of exactly the novel part |
| Confounded changes | Several changes shipped together (architecture + data + training recipe) | Factorial or one-at-a-time ablation |
| Leakage | Validation used for early stopping *and* reporting; test used for selection | Separate dev/test; selection protocol stated |
| Statistical weakness | Single seed, no variance, gains smaller than seed noise, cherry-picked checkpoints | Multiple seeds; CI; gains vs. reported variance |
| Implementation gap | Baseline numbers copied from other papers with different setups | Re-run baselines under the same harness |

## External validity — how far does the claim generalize?

| Dimension | Ask |
|---|---|
| Datasets / tasks | How many, how diverse, who chose them, were any dropped? |
| Model families | One architecture, one pretraining corpus? Does it hold for a second family? |
| Scale | Shown at 1B, claimed for all? Any scaling trend, or just one point? |
| Domains / languages | English-only, single domain, synthetic-only? |
| Distribution shift | Any OOD or robustness evaluation, or only i.i.d. test splits? |
| Deployment conditions | Latency, memory, cost, failure modes, safety; does the gain survive quantization/serving constraints? |
| Negative results | Are there settings where it did *not* help, and are they reported? |

## Severity reminders

- A threat is **Fatal** only if it offers a plausible *complete* alternative explanation of the
  headline result, or the headline result is unsupported by the paper's own numbers.
- A threat is **Major** if it undermines a main claim in an important regime or makes the
  headline gain unattributable to the novel component.
- Missing error bars are **Moderate** by default and **Major** only when the gains are small
  enough that noise is a credible explanation.
- "Would be nice to see X" with no path from X to overturning a claim is **Minor** and usually
  not worth a bullet.
